# ADR-001: 單一 repo、多模組 Maven

狀態：已採納

## 背景

這個專案會有三到四個可獨立部署的服務（discovery-server、api-gateway、order-service，
之後還有 inventory-service）。微服務的典型做法是一個服務一個 repo。

## 決定

全部放在同一個 repo，用 Maven 的 parent + modules 結構。

## 理由

拆 repo 要解決的問題是「不同團隊、不同發布節奏、不同權限邊界」。這個專案三者都沒有：
一個人開發、一起發布、同一份權限。

反過來，拆 repo 的成本是實際存在的：

- 共用的依賴版本（Spring Boot、Spring Cloud）要在多處同步，很容易漂移
- 跨服務的改動（例如改 API 契約）要開多個 PR，而且無法一起 review
- 本機要 clone 多個 repo 才能跑起來

單一 repo 還有一個對這個專案特別重要的好處：**版本相容性只需要在一個 parent pom 裡維護一次**。
Spring Boot 4.0.8 與 Spring Cloud 2025.1.3 的搭配是查證過的，不想在四個地方重複這件事。

## 取捨

- 所有模組被迫共用同一組依賴版本。真的需要某個服務用不同版本時會很彆扭
- CI 預設會建置整個 reactor，即使只改了一個模組。模組變多之後要做路徑過濾
- 給外人看的時候，repo 體積比單一服務大

## 後續

出現以下任一情況就該重新考慮：有第二個人／團隊只負責其中一個服務；
某個服務的發布頻率明顯不同於其他；某個服務必須用不一樣的框架版本。
